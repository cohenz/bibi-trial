# Cloudflare R2 — הגדרה מאובטחת

ההחלטה והנימוקים מופיעים ב־ADR‑0011. כאן ההוראות המעשיות.

## Buckets
| bucket | תוכן | גישה ציבורית |
|---|---|---|
| `ntk-sources` | קובצי PDF של הפרוטוקולים: `sources/sha256/<aa>/<sha256>.pdf` | **כבויה.** לא r2.dev ולא custom domain |
| `ntk-backups` | גיבויי DB יומיים: `db/YYYY/MM/DD/…` | כבויה |

ציטוט ציבורי מוביל ל־permalink במערכת (`/v2/citations/{id}`), שמציג את הטקסט, העמוד והשורה. הקובץ עצמו אינו נחשף ישירות.

## API tokens (עיקרון: הרשאה מינימלית)
R2 → Manage R2 API Tokens → Create API token:

| token | הרשאה | Buckets | שירותים |
|---|---|---|---|
| `ntk-app` | Object Read & Write | `ntk-sources` בלבד | api (presign + HEAD), worker (קריאה; כתיבה רק בקליטה מ־URL) |
| `ntk-backup` | Object Read & Write | `ntk-backups` בלבד | backup |

- ל־R2 אין token שמאפשר presign לכתיבה בלי הרשאת כתיבה. לכן ה־API מקבל Read & Write. הגנה מפני דריסה ומחיקה מגיעה מ־Bucket Lock (למטה), לא מה־token.
- אין Admin token באף שירות.
- הערכים נשמרים כ־Railway Variables בלבד: `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, ובשירות backup `BACKUP_ACCESS_KEY_ID`, `BACKUP_SECRET_ACCESS_KEY`. **לא ב־WordPress, לא בריפו ולא בצ'אט.**
- רוטציה: יוצרים token חדש, מעדכנים Variables ועושים redeploy, ואז מוחקים את הישן.

## CORS (רק ל־`ntk-sources`)
העלאה מהדפדפן נעשית ב־PUT ישיר ל־presigned URL. ההגדרה המלאה ב־`docs/install.md` §2. מגבילים ל־origin של אתר ה־WordPress בלבד.

## Bucket Lock (retention)
`ntk-sources` → Settings → Bucket Lock Rules → Add rule:
- prefix: `sources/`
- retention: לפחות שנה, או "indefinite" אם רוצים שמקור לא יימחק לעולם.

בתקופה הזו אי אפשר למחוק או לדרוס אובייקטים, גם עם token כתיבה. זה התחליף ל־object versioning, ש־R2 אינו תומך בו.

## הצפנה
R2 מצפין את כל האובייקטים במנוחה (AES‑256) כברירת מחדל. התעבורה היא HTTPS בלבד.
