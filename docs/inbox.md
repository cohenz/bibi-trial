# תיבת הקליטה (inbox) — העלאה מרוכזת וקליטה יומית

מסמכים חדשים נכנסים למערכת דרך תיקייה אחת ב־R2: הקידומת `inbox/` ב־bucket `ntk-sources`. אפשר לשים בה כל מבנה של תת־תיקיות. המערכת לא מוחקת ולא משנה שום קובץ בתיקייה.

## מה קורה לכל קובץ
1. **רישום.** כל קובץ חדש נרשם לפי מפתח ו־ETag בטבלה `ntk.inbox_items`. קובץ שהוחלף באותו שם נרשם כפריט חדש.
2. **סיווג.** המערכת קוראת את העמודים הראשון, השני והאחרון, ומריצה OCR אם אין שכבת טקסט.
   - **כללים:**
     - כותרות: פרוטוקול, החלטה, הכרעת דין, גזר דין, בקשה, תגובה, הודעה, תצהיר, כתב אישום;
     - "ניתנה היום" בסוף המסמך;
     - מספרי תיקים;
     - תאריכים.
   - **כשהכללים לא בטוחים** (ביטחון מתחת ל־0.7), המודל מסווג. הוא מקבל רק את העמודים האלה.
3. **סינון:**
   - **`duplicate`:** כפילות מדויקת לפי SHA‑256 של מקור שכבר נקלט, או של פריט אחר בתיבה.
   - **`foreign_case`:** במסמך מודפסים מספרי תיקים, ואף אחד מהם אינו 67104-01-20.
   - **`unsupported`:** קבצים שאינם PDF.
4. **העתקה.** הקובץ מועתק לכתובת הקבועה `sources/sha256/…`, שמוגנת ב־Bucket Lock.
5. **קליטה** (כשהעיבוד פעיל). כל פריט מסווג הופך למשימת קליטה רגילה:
   - **פרוטוקול:** דוברים, ש/ת, תקציר ומאמת, כמו עד היום.
   - **שאר הסוגים:** החלטה, בקשה, תגובה, הודעה, תצהיר, כתב אישום, מוצג ואחר.
     - יחידות ציטוט הן פסקאות, עם עמוד ושורות;
     - יש chunks ו־embeddings;
     - בהחלטה, הפסקאות מיוחסות ל"בית המשפט";
     - אין עדיין תקציר AI למסמכים שאינם פרוטוקולים.
6. **פרסום.** פרוטוקולים והחלטות מתפרסמים אוטומטית, אבל רק כשמספר התיק מודפס על המסמך עצמו. שאר הסוגים, וכל שכבות ה־AI, ממתינים לאישור.

## לוח זמנים
- **סריקה יומית:** ב־02:47 UTC, כלומר 05:47 בשעון ישראל בקיץ ו־04:47 בחורף. הסריקה נעשית ב־beat, והשעה נקבעת ב־`NTK_INBOX_SCAN_HOUR_UTC` וב־`NTK_INBOX_SCAN_MINUTE`.
- **`NTK_INBOX_AUTO_PROCESS=false`** (ברירת המחדל): הסריקה רק מסווגת, כלומר מכינה "מפה". קליטה מתחילה רק כשמפעילים אותה.
- **`NTK_INBOX_AUTO_PROCESS=true`:** כל פריט שסווג נקלט מיד. זה המצב המיועד אחרי שהמפה הראשונה אושרה.

## API (admin, חתום)

| קריאה | מה היא עושה |
|---|---|
| `POST /v2/admin/inbox/scan` `{"process": false}` | סריקה עכשיו. `false` לסיווג בלבד, `true` לסיווג וקליטה, `null` לפי ההגדרה |
| `GET /v2/admin/inbox?status=&kind=&limit=&offset=` | תמונת מצב: לפי סטטוס ולפי סוג, פריטים בביטחון נמוך, סריקות אחרונות ורשימת פריטים |
| `POST /v2/admin/inbox/process` `{"kinds": ["protocol","decision"]}` או `{"item_ids": [...]}` | קליטה של פריטים מסווגים |
| `POST /v2/admin/inbox/items/{id}` `{"source_type": "response"}` או `{"skip": true}` | תיקון סיווג ידני, או דילוג על פריט |

## איך מעלים
- **מעט קבצים:** דשבורד Cloudflare ← R2 ← `ntk-sources` ← יוצרים תיקייה `inbox` ← Upload. הדשבורד מקבל גרירה של קבצים רבים.
- **מאות קבצים:** `rclone copy <תיקייה מקומית> r2:ntk-sources/inbox/ --progress`. צריך token של R2 עם הרשאת Object Read & Write על `ntk-sources`. את ה־token מגדירים במחשב שלך, והוא לא עובר בצ'אט.
