- **פריסה:** GraphQL `serviceInstanceDeployV2(serviceId, environmentId, commitSha)` מלשונית Railway המחוברת בדפדפן המובנה (`fetch("https://backboard.railway.com/graphql/v2", {credentials: "include"})`). מזהים ב־`deployment-state.md`. api ראשון כשיש migration. פריסה של worker הורגת משימה רצה — `python tools/ops.py stuck` אחר כך.
- **לוגים:** `deploymentLogs(deploymentId, filter, limit)` באותו GraphQL.
- **קריאות admin:** `tools/ops.py` (חתימה ב־HMAC). הסוד **לא** ב־repo ולא בצ'אט: `NTK_OPS_SECRET_FILE=<קובץ>` או `NTK_OPS_SECRET`. בשיחה חדשה הסוד של `claude-ops` לא זמין. **מפתח חדש:** באישור המשתמש, ליצור סוד אקראי בסביבה, ולכתוב אותו ישירות למשתנה `NTK_SERVICE_KEYS_EXTRA` של api (JSON: `{"<key_id>": {"secret": "...", "scopes": ["admin:read","admin:ingest","admin:publish"]}}`) דרך `variableCollectionUpsert` מהדפדפן, ואז לפרוס api (גם זו פריסה — צריך אישור). אסור לקרוא את `NTK_SERVICE_KEYS` הקיים.
- **פקודות שימושיות:** `python tools/ops.py status` · `stuck` · `failed` · `call GET /v2/admin/batches`.
- **בדיקות:** `NTK_TEST_ADMIN_URL=postgresql+psycopg://ntk:ntk@localhost:5432/postgres python -m pytest -q` (Postgres מקומי; אם הסיסמה נדחית — `ALTER ROLE ntk PASSWORD 'ntk'`). בתוסף: `php wordpress/trial-knowledge/tests/run.php`. בניית ZIP: `bash tools/build_plugin_zip.sh` → `dist/` (לא ב־git; שולחים למשתמש).
- **עלויות:** המשתמש רגיש לעלויות — כל שליחה גדולה לג'מיני רק באישור, עם ניסיון קטן קודם.
